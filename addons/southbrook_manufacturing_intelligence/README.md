# Southbrook Manufacturing Intelligence

Pre-release checks that surface why an MO can't ship — cut, production,
assembly, install, cad, hardware categories with blocker / warning /
info severities.

## Models

- `southbrook.mi.engine` — AbstractModel; recomputation entry points
  `_recompute_production(mo)` and `_recompute_package(package)`.
- `southbrook.mi.check` — the persisted check records.

## Audit P-task owned here

### P3 — Auto-remediation of `Missing cutlist`

When `_recompute_production` would create a `Missing cutlist` blocker
**AND** the source `sale.order.line` carries a complete configuration
(Width present; Door Style isn't a "Custom …" value), the engine calls
`sb.production.package.build_from_order_line(order_line, mo=production)`
and re-evaluates. On success the blocker is suppressed and an
info-severity `Cutlist auto-generated` check carries the audit note
(`Auto-generated by MI on <ts> (audit P3 — …)`).

`CAD not complete` is intentionally NOT auto-cleared — it stays a
human gate per the audit's hard rule.

Gated behind `ir.config_parameter
southbrook_manufacturing_intelligence.auto_remediate_cutlist` (default
**OFF**).

## Rollback

P3 → set `auto_remediate_cutlist=False`. Existing checks survive; the
auto-generated cutlist on a previously-remediated MO continues to work
because nothing about it is special — it's the same cutlist model the
manual flow produces.
