## Why this isn't landed autonomously

The Track C agent's analysis flagged risks that pricing-side patches shouldn't be auto-applied without confirmation:

1. **Only 1 of 6 anchors has a known number.**
   - `box_maple` — `list_price × 0.10` per CLAUDE.md §5 Rule 2 (canonical).
   - Other 5 anchors — Price Master tab of `Southbrook_Consolidated_Dataset.xlsx` has the real values, but this session couldn't extract them.

2. **3 of 6 anchor names don't map cleanly to seeded xml_ids:**

   | Original label | Nearest xml_id | Issue |
   |---|---|---|
   | `hinge_soft_close` | `value_accessory_soft_close` | Soft-close is a MULTI-SELECT accessory upgrade, not a hinge value. Attribute is `attr_accessories`, not `attr_hinge_side`. OCA `get_attribute_value_extra_prices` still sums multi-select PTAV extras, so this works — but the label is misleading. |
   | `finish_premium_colors` | `value_finish_custom` (PLACEHOLDER) | Current `attr_finish` set (White / Maple Stain / Cherry Stain / Walnut Stain / Custom) is NF19 phase-1 placeholders. "Premium finish" doesn't cleanly land on one row. **Needs product-owner mapping.** |
   | `hardware_blum` | `value_drawer_metal_blum` (PLACEHOLDER) | Blum Legrabox is a drawer BOX CONSTRUCTION, not pull hardware. If "Blum hardware" means Blum HINGES, there is no `attr_hinge_hardware` attribute — would need to add one first. |

3. **Data-only patch is technically impossible.** PTAV rows are auto-generated by Odoo — no xml_ids to `<record>` against. A small AbstractModel helper (~40 lines) is required to search + write from a declarative XML data file. This mirrors the existing tactical seed in `southbrook_configurator_ux/models/tactical_price_seed.py`.

## The three questions the product owner needs to answer

**Q1.** Does `finish_premium_colors` refer to:
- (a) The `Custom` slot in the current NF19 attr_finish placeholder set?
- (b) A different premium-color anchor that needs a new attr_finish value first?
- (c) Something entirely different (e.g. `value_species_walnut` on the new attr_wood_species)?

**Q2.** Does `hardware_blum` refer to:
- (a) Blum Legrabox drawer BOX construction (existing `value_drawer_metal_blum` on `attr_drawer_construction`)?
- (b) Blum HINGES (would need to add a new `attr_hinge_hardware` attribute)?
- (c) Blum-branded HANDLES (would need a new `attr_handle_brand` attribute)?

**Q3.** Numbers from `Southbrook_Consolidated_Dataset.xlsx` Price Master tab for each anchor × each of the 12 canonical templates. The XML shape is a nested dict:

```xml
[ 'value_series_signature', {
    'wall_1dr':  <NUMBER>,
    'wall_2dr':  <NUMBER>,
    ... one row per applicable template
} ],
```

Not every anchor applies to every template — e.g. `door_five_piece_woodgrain` only lives on 10 of 12 (worktop + accessory don't have door_style). If a number is 0 or the anchor doesn't apply, leave the template row out entirely (the seed helper silently skips missing rows).
