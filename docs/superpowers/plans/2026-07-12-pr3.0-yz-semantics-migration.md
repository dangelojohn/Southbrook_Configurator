# PR3.0 — Wall-Cabinet y/z Field-Semantics Migration (y = canonical elevation)

**Lead decision (2026-07-12):** PR3 splits into PR3.0 (this migration) + PR3.1 (renderer
dual-path collapse). `y_position_in` becomes the canonical mount-height/elevation field;
`z_position_in` returns to its contract meaning (depth/plan-Z). PR3.1 is BLOCKED on this.

## Why (from the coordinate-contract matrix, docs/2026-07-12-pr3-coordinate-contract-matrix.md)
The backend configurator's two writers persist wall-cabinet mount-height into
`z_position_in` with `y_position_in` hardcoded 0, and the legacy builders read it back
from z into the THREE **Y** slot. The engine, meanwhile, already emits y=1400mm for the
upper zone (`_ZONE_LAYOUT`, kitchen_layout_engine.py:129, sale_order.py:417) — so the two
conventions collide the moment an upper cabinet lands on a side wall (where engine-z =
along-axis). Collapsing the renderer paths before this fix would misplace every wall
cabinet (mount-height read as depth; elevation 0). Verified live: **83/83** wall-type
design lines in prod have the legacy shape (y=0, z≈55); discriminator below is exact.

## Canonical semantics (after PR3.0)
- `y_position_in` — elevation in inches, floor → cabinet bottom (0 for floor-standing).
- `z_position_in` — world plan-Z per COORDINATE_CONTRACT.md (depth axis; engine-owned for
  side walls). Backend back-wall items: 0 (flush).
- `rotation_deg` — unchanged.

## Scope (single module unless stated; stacked on PR2.5a's branch result)

1. **Migration** — `migrations/<bumped version>/post-migration.py`:
   - `southbrook_kitchen_design_line`: `UPDATE ... SET y_position_in = z_position_in,
     z_position_in = 0 WHERE cabinet_type = 'wall' AND COALESCE(y_position_in,0) = 0 AND
     z_position_in >= 30` (same treatment for 'panel'/'other' rows matching the shape —
     matrix rows: buildOtherCabinet/buildEndCapPanel share the z-as-height read; verify
     shapes per type in SQL before including them, report counts).
   - Mirrored `sale_order_line.sb_layout_y_mm` / `sb_layout_z_mm` (reconcile mirrors raw):
     same discriminator translated to mm; verify against live shapes first.
   - Manifest version bump. Idempotent (re-run safe: discriminator excludes migrated rows).
2. **Writers** (both, in lockstep):
   - `controllers/main.py` `_layout_item` (~L165): emit `y=wall_z, z=0` for uppers (and
     any other z-as-height emission in the /layout fill path).
   - `kitchen_configurator.js`: `_addCabinetFromProduct` wall-type default → seed
     `y_position_in` (WBY-equivalent inches) with `z_position_in: 0`; the D8
     alignment/swap path (~L694-736) likewise moves mount-height writes z→y.
3. **Builder reads** (keeps the LEGACY render path correct with migrated data — PR3.1
   collapses paths later): `wall_cabinet.esm.js` (`wbY` from `y_position_in`),
   `other_cabinets.esm.js` (`buildOtherCabinet`/`buildEndCapPanel` z0 → y0). The
   `__localFrame` zeroing behaviour must be preserved.
4. **Enforcement test upgrade**: `tests/test_coordinate_contract.py` — add placement-
   semantics assertions (a wall-type line's mount-height lives in y; z of a back-wall
   upper is 0), not just field presence. Remove the y/z entries from the "known migration
   debt" set the matrix cites, so regressions fail loudly.
5. **Server round-trip tests**: extend TestWallPersistence/TestSaveLoadIdentity fixtures
   to include an upper with nonzero y — identity must hold.
